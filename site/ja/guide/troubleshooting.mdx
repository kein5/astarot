# 困ったとき

症状に近い見出しを探してください。VRChatに声や文字が届かないときは、最初の節から見ます。

## VRChatに届かない

### VRChatのチャットボックスにメッセージが出ない

- 「設定」→「VRChat」を開きます。ページの先頭に、OSCが有効なVRChatをお使いのPCで検出できたかが出ます。メイン画面の「クイック設定」にも同じ表示があります。
- 「検出できません」と出るときは、VRChatを起動し、アクションメニューで「Options」→「OSC」を「Enabled」にします。少し待つと表示が変わります。
- ログに「VRChatには未送信（設定でオフ）」と出たメッセージは、「VRChatにメッセージを送信する」がオフのために送っていません。「設定」→「VRChat」でオンにしてください。
- VRChatを見つけられたかどうかは、お使いのPCの中で<Term tip="OSCを使うアプリどうしが相手のポートと受け取れる値を見つけるための仕組みです。">OSCQuery</Term>という仕組みを使って確かめています。そのため送信先が別のPCのときは「確認できません」と出ますが、メッセージは送ります。また、ファイアウォールがPCの中での探索（<Term tip="サーバーを使わずに、同じPCや同じネットワークの中の機器やサービスを名前で探す仕組みです。">mDNS</Term>）を止めていると、「検出できません」と出たままでもメッセージは届くことがあります。
- 「設定」→「高度な設定」の「OSCQueryを使う」をオフにしていると、VRChatの状態は確認しません。その間もメッセージは送りますが、VRCマイクミュート同期は使えません。

### 読み上げがVRChatで聞こえない

1. メイン画面の上のボタンに「ミュート中」と出ていたら、ミュートされています。「設定」→「デバイス」→「詳細設定」→「音声経路」で「ミュートを解除」を押します。
2. 「設定」→「テキスト読み上げ（TTS）」の出力先と、VRChatのマイクの選択が合っているかを確かめます（[Windowsの音声経路](./windows-audio)、[Linuxの音声経路](./linux-audio)）。
3. 同梱サーバーが起動しているかを確かめます。アプリを再起動するとサーバーは停止した状態に戻ります。
4. VRChatのマイクテストは少しの間録音してから再生する仕組みです。VRChatのマイクの入力メーターが動いている間にテストを始めてください。

### 二重に読み上げられる

VRCT-TTSなど、同じチャットを読み上げる別のツールをオフにしてください。

## 起動とマイク

### マイクが開けない（Windows）

Windowsのバージョンによっては、マイクを初めて使うときに、ASTAROTにマイクの使用を許可するかどうかを確認します。許可してからもう一度開始してください。

ファイアウォールの確認など、ほかの確認の画面が開いている間も、マイクは使えません。その確認に答えてからもう一度開始してください。

0.6.0からは、VRChatとのやり取り（OSCとOSCQuery）でファイアウォールの確認は出ません。0.5までの版は、VRChatがOSCQueryという仕組みでASTAROTを見つけられるようにするための通信を、許可するかどうかをこの確認で聞いていました。0.5までの版で確認が出たときは、「アクセスを許可する」を選んでください。キャンセルしたり閉じたりすると、WindowsはASTAROTの受信をブロックする規則を作ります。

マイクの確認に答えないままASTAROTを閉じると、次からは確認が出ずに、マイクの使用が拒否されます。設定の「プライバシーとセキュリティ」→「マイク」を確かめてください。

### もう一度起動しても、新しいウィンドウが開かない

ASTAROTは同時に1つだけ動きます。動いている間にもう一度起動すると、動いているウィンドウを前に出します。

### ウィンドウが真っ黒・何も表示されない（Linux）

- モニターがスリープしている間は、デスクトップがウィンドウを描かないため、画面が止まったように見えます。モニターを点けてから確かめてください。
- NVIDIAのGPUでは、AppImageが表示の不具合を避けるための設定を自動で入れます。このときウィンドウの透明化は使えません。

## 機能とモデル

### モデルがないと表示される

その機能のページでモデルを取得して「モデルパスを適用」まで行ってください（[モデルの取得](./models)）。読み上げや音声認識ではそのあと「サーバーを起動」も必要です。

### 自分で用意したモデルが動かない

アプリは自分で指定したファイルについて、拡張子や形式など最小限のことしか確かめません。出たメッセージと、機能ごとに確かめることは[自分のモデルを使う](./custom-models)にあります。

### チャット読み取りで「ウィンドウが見つかりません」と出る

- VRChatを起動してから、チャット読み取りをオンにしてください。
- 「設定」→「チャット読み取り（OCR）」の「ウィンドウ名」が、使っているクライアントのタイトルと合っているかを確かめてください。初期設定は`VRChat`です。
- Linuxでは、VRChatがX11/XWaylandのウィンドウとして動いているとき（Protonの初期設定）に、ウィンドウ名で探せます。gamescopeの中など、ネイティブのWaylandのウィンドウとして動いているときは、先にウィンドウを共有してください（[チャット読み取り](../features/chat-reading)）。

### 音声タイピングモードで貼り付けられない（Linux）

- 貼り付けられるのは、X11/XWaylandのウィンドウとして動いているアプリです。Protonの初期設定では、VRChatはこの形で動きます。ネイティブのWaylandのウィンドウには貼り付けられません。このときも、文はクリップボードへコピーされているので、手動で貼り付けられます。
- KDEでは初めて貼り付けるときに、入力デバイスの操作を許可するかどうかをデスクトップが確認します。許可してください。
- 貼り付け先はSteamVRで実行中のアプリのウィンドウです。SteamVRが動いていないときは、クリップボードへコピーするだけです。

### 翻訳モデルを取得しても「翻訳」がオンにならない（Windows）

0.1.0-beta.6までのWindows版にあった不具合です。取得の確認画面が何度も開き、翻訳がオンになりません。0.1.0以降に更新してください。

## ログと報告

### ログの場所

| OS | 場所 |
|---|---|
| Windows | アプリのフォルダーの`logs` |
| Linux | <CopyText>\~/.config/astarot/logs</CopyText>（0.5.xまでは<CopyText>\~/.config/vrct-vox/logs</CopyText>） |

### 不具合を報告する

[ASTAROTのIssues](https://github.com/kein5/astarot/issues)に次のことを書いてください。

- OSと、ASTAROTのバージョン
- 起きたことと、そこまでの手順
- ログ。個人情報、APIキー、会話の内容は消してから貼ってください

::: info 本家VRCTへは報告しないでください
ASTAROTについての質問や報告を、本家VRCTの開発者へ送らないでください。
:::

セキュリティの問題は公開のIssuesではなく[SECURITY.md](https://github.com/kein5/astarot/blob/develop/SECURITY.md)の方法で非公開で知らせてください。
