# インストール

配布物は[GitHub Releases](https://github.com/kein5/astarot/releases)にあります。正式版には「Latest」の印が付きます。ベータ版は「Pre-release」として公開しています。対応するOSと、機能ごとに必要なメモリ、GPU、空き容量は[動作環境と推奨スペック](requirements)にあります。

Windowsはこのすぐ下、Linuxは[Linuxの節](#linux)にあります。

## Windows

1. [GitHub Releases](https://github.com/kein5/astarot/releases)で「Latest」の印が付いた版の「Assets」から、`VRCT-VOX_setup.exe`をダウンロードします。
2. ダウンロードしたファイルを開きます。SmartScreenの警告が出たときは、下の注意のとおりに進めます。
3. 途中でCPU版かGPU版を選びます。0.5.0から2つの中身は同じなので、どちらを選んでも同じように動きます。
4. インストールが終わったら、ASTAROTを起動して[最初の設定](./first-setup)へ進みます。

::: warning 初めて起動するときにSmartScreenの警告が出ます
Windows版はコード署名をしていません。「WindowsによってPCが保護されました」と出たら、「詳細情報」を押してから「実行」を押します。
:::

0.5.0からCPU版とGPU版（CUDA版）の中身は同じです。以前のGPU版はローカルの翻訳をNVIDIAのGPUで動かすための版でした。いまはどちらの版でもローカルの翻訳はCPUで動きます。読み上げとリアルタイム字幕（アプリに入っているspeech.cpp）は、どちらの版でもGPUを使えます。

VRChatへ声を届けるには、仮想ケーブルも必要です（[Windowsの音声経路](./windows-audio)）。

### インストールせずに使う（ZIP）

インストールせずに、展開したフォルダーから使いたいときはZIPを使います。

- `VRCT-VOX.zip`（CPU版）
- `VRCT-VOX_cuda.zip`（CUDA版。0.5.0から中身は`VRCT-VOX.zip`と同じです）

::: details 設定とデータの場所（Windows）
設定（`config.json`）、ログ、取得したモデルは、アプリを入れたフォルダーの中にあります。

| 入れ方 | 場所 |
|---|---|
| インストーラー | <CopyText>%LOCALAPPDATA%\VRCT-VOX</CopyText>（インストール先を変えていない場合） |
| ZIP | 展開したフォルダー |
:::

## Linux

x64向けの<Term tip="GPUで描画や計算をするための仕組みです。NVIDIA、AMD、IntelのGPUのドライバーが対応しています。">Vulkan</Term>版を、deb、rpm、AppImage、tar.gzの4つの形で配布しています（debとrpmは0.3.0から）。ファイルが壊れていないかは、[ダウンロードを確かめる](#ダウンロードを確かめる)の方法で確かめられます。

### deb（Ubuntu、Debian）

```sh
sudo apt install ./VRCT-VOX-<バージョン>-linux-x64-vulkan-release.deb
```

アプリは`/opt/vrct-vox`に入り、アプリの一覧に「VRCT-VOX」が出ます。端末からは`vrct-vox`で起動できます。新しいバージョンも同じコマンドで入れます。消すときは`sudo apt remove vrct-vox`を実行します。

### rpm（Fedora）

```sh
sudo dnf install ./VRCT-VOX-<バージョン>-linux-x64-vulkan-release.rpm
```

入る場所と起動のしかたはdebと同じです。消すときは`sudo dnf remove vrct-vox`を実行します。

debとrpmは、Ubuntu 24.04、Debian 13、Fedora 44で、入れられることと、必要なライブラリがそろうことを確かめています。PipeWireのツールとVulkanのドライバーは推奨のパッケージとして入ります。

### AppImage

```sh
chmod +x VRCT-VOX-<バージョン>-linux-x64-vulkan-release.AppImage
./VRCT-VOX-<バージョン>-linux-x64-vulkan-release.AppImage
```

<Term tip="アプリがカーネルを変えずにファイルシステムを用意できる、Linuxの仕組みです。AppImageは起動するときに使います。">FUSE</Term>を使えない環境では、<CopyText>APPIMAGE_EXTRACT_AND_RUN=1</CopyText>を付けて起動します。このときは、展開のための一時的な空き容量が別に必要です（確かめたバージョンでは約1.7 GB）。

### tar.gz

```sh
tar -xzf VRCT-VOX-<バージョン>-linux-x64-vulkan-release.tar.gz
./VRCT-VOX/vrct-vox
```

展開した`VRCT-VOX`フォルダーの中身はばらさずにそのまま置いておいてください。WebKitGTK 4.1、GTK 3、PipeWire、VulkanなどはOSに入っているものを使います。どのディストリビューションでも動くことを約束するものではありません。

::: details 設定とデータの場所（Linux）
| 内容 | 場所 |
|---|---|
| 設定とログ | <CopyText>\~/.config/vrct-vox</CopyText>（`$XDG_CONFIG_HOME`があればその下） |
| データ | <CopyText>\~/.local/share/vrct-vox</CopyText> |
| キャッシュ | <CopyText>\~/.cache/vrct-vox</CopyText> |

deb、rpm、AppImage、tar.gzのどれで起動しても、同じ場所を使います。
:::

## ダウンロードを確かめる

各ファイルに`.sha256`があり、まとめた`SHA256SUMS-*`もあります。どちらもファイルが壊れていないかを確かめるためのもので、署名ではありません。

Windowsのインストーラーは取得したZIPを自分で確かめます。0.3.0からは、同じリリースのZIPのSHA-256がインストーラーに入っていて、リリースのページのファイルが差し替えられても、違うZIPは展開しません。

Linuxでは、ダウンロードしたファイルと同じフォルダーに`SHA256SUMS-linux`も置いて、次を実行します。

```sh
sha256sum -c --ignore-missing SHA256SUMS-linux
```

::: details ビルドの来歴を確かめる（0.3.0から）
各ファイルにはビルドの来歴が付きます。来歴には、このリポジトリのどのワークフローが、どのコミットからそのファイルを作ったかが書かれていて、GitHubが署名しています。来歴はこのリポジトリのワークフローの中でしか作れないので、リリースのファイルを差し替える権限だけでは作れません。

確かめるには[GitHub CLI](https://cli.github.com/)を入れて、ダウンロードしたフォルダーで次を実行します。ファイル名は確かめたいものに替えてください。

```sh
gh attestation verify VRCT-VOX_setup.exe --owner kein5 --signer-repo kein5/VRCT-VOX
```

0.5.0までのファイルは、リポジトリの名前を`kein5/astarot`に変える前に作ったので、来歴には古い名前の`kein5/VRCT-VOX`が書かれています。そのため、上のように持ち主（`kein5`）と古い名前を指定します。0.5.0より後のファイルは`gh attestation verify ファイル名 --repo kein5/astarot`で確かめます。

「Verification succeeded!」と出れば、そのファイルはこのリポジトリのワークフローで作られています。失敗した場合は、そのファイルを使わずにIssueで知らせてください。
:::

## 更新

新しいバージョンが出ると、画面上部に「新しいバージョンが出ました！」と出ます。「設定」→「アップデート」でも確かめられます。どう更新するかは、入れ方で変わります。

| 入れ方 | 更新のしかた |
|---|---|
| Windowsのインストーラー | 「アップデート」の「（バージョン）に更新して再起動」で更新します。ダウンロードした更新は署名を確かめてから入れ、終わるとASTAROTが再起動します |
| AppImage | 同じボタンで、AppImageのファイルを新しいものに置き換えます |
| WindowsのZIP、Linuxのtar.gz | 新しいバージョンがあることだけを知らせます。GitHub Releasesから入れ直してください |
| deb、rpm | アプリは更新を確認しません。パッケージマネージャーで更新してください |

起動時の確認は「アップデート」の「起動時に更新を確認する」で止められます。確認に失敗しても、アプリはそのまま使えます。設定とダウンロードしたモデルは上の場所に残ります。

Windowsのインストーラーは新しいバージョンを展開して確かめてから古いバージョンと置き換え、途中で失敗したときは古いバージョンに戻します。設定、モデル、ログは消しません。

::: warning ZIPで使っている場合
設定とモデルは展開したフォルダーの中にあります。新しいZIPを別のフォルダーへ展開すると引き継がれません。更新のたびに引き継ぎたいときはインストーラーを使ってください。
:::

## 起動は1つだけ

ASTAROTが動いている間にもう一度起動すると、もう1つは起動せず、動いているウィンドウを前に出します。

次は[最初の設定](./first-setup)へ進んでください。
