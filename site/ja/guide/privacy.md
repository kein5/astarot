# プライバシー

## 利用状況の送信

ASTAROTは次の2種類の通知をASTAROTの開発者へ送ります。不具合を直し、どのPCでどの機能が快適に動くかを調べるためです。「設定」→「高度な設定」の「利用状況を送信する」でオフにできます。

| 通知 | いつ | 内容 |
|---|---|---|
| 起動した | 1日に1回 | 送信した時刻、アプリのバージョン、OSの種類とバージョン、表示言語、PCの構成 |
| エラーが起きた | 同じ種類のエラーにつき1日に1回 | 上と同じ内容と、エラーの種類を表す固定の名前（エラーコード） |

PCの構成として送るのは次の内容です。

- CPUの名前と論理コア数
- メモリの量（8GB、16GB、32GBのような区切りに丸めた値）
- GPUの名前、内蔵か単体かの別、ビデオメモリの量、ドライバのバージョン（最大4台。ドライバのバージョンは読み取れる場合だけ）

![利用状況の送信をお願いする画面](/screenshots/ja/telemetry-notice.webp)

送られる内容は送信を始める前のお知らせ（上の画面）と「高度な設定」にある「送信される内容を見る」で確かめられます。お使いのPCから送る内容が項目ごとに並び、送るデータそのものと、これまでに送った内容の一覧（「高度な設定」だけ）も表示できます。

- 会話の文字や音声、マイクやスピーカーの名前、ユーザー名、PCの名前、ファイルの場所は送りません。
- 受信サーバーは送信元のIPアドレスやPCを見分ける番号を保存しません。ただし受信サーバーはCloudflareの上で動いているため、通信を受けるCloudflareは送信元のIPアドレスを受け取ります。
- 受信サーバーは通知を受け取った時刻と、接続元のアドレスから分かる国を記録します。
- PCを見分ける番号は送りませんが、PCの構成が珍しいと、その組み合わせから同じPCの通知だと推測できることがあります。
- 送信を始める前に、送る内容を説明する画面が出ます。「送信する」か「送信しない」を選ぶまで、何も送りません。「あとで決める」を選ぶと、次に起動したときにもう一度出ます。
- 環境変数`ASTAROT_TELEMETRY`に`off`を入れて起動すると、設定にかかわらず送りません。以前の名前の`VRCT_TELEMETRY`も使えます。

本家VRCTにある利用状況の送信（Aptabaseのテレメトリー）は使っていません。古い設定のキーファイルが残っていても、本家へは送りません。

## 外部へ送られるもの

利用状況の送信を止めても、すべての機能がオフラインになるわけではありません。ご自身で選んだサービスには、そのサービスを使うために必要なものが送られます。

| 使う機能 | 送り先 | 送られるもの |
|---|---|---|
| 外部の翻訳API（DeepL、Google Cloud、Papago） | 選んだサービス | 翻訳する文章 |
| LLMの翻訳エンジン（OpenAI、Gemini、Groq、OpenRouter、Plamo、OpenAI互換、LM Studio、Ollama） | 選んだサービスやサーバー | 翻訳する文章と、直近の会話を最大5件。会話はチャットとマイクの自分の発言と、スピーカーから聞き取った相手の発言です。それぞれに言った時刻（時:分）が付きます |
| 翻訳エンジンと音声認識エンジンの確認 | APIキーを保存したサービス | APIキーと、モデルの一覧の問い合わせ。起動したときは選んでいるエンジンにだけ送り、ほかのエンジンには選んだときに送ります。会話は送りません |
| クラウドの音声認識（Groq Whisper、OpenAI Whisper、Deepgram、カスタムWhisperサーバー） | 選んだサービスやサーバー | 話し終わるごとの音声 |
| モデルの取得 | Hugging Face | ダウンロードの要求 |
| ボイスチェンジャー（RVC）の実行環境の取得 | Hugging Face、NuGet（`api.nuget.org`。ONNX Runtime）、PyPI（`files.pythonhosted.org`。NVIDIAのGPUで動かすときのライブラリ） | ダウンロードの要求 |
| 翻訳をGPUで動かす実行環境（ONNX RuntimeのCUDA版、DirectML版）の取得 | NuGet（`api.nuget.org`）、PyPI（`files.pythonhosted.org`。CUDA版のときのNVIDIAのライブラリ） | ダウンロードの要求 |
| 翻訳のLLMを動かすllama.cppのサーバーの取得 | GitHub（`github.com`、`release-assets.githubusercontent.com`） | ダウンロードの要求 |
| チャットボックスへの送信 | VRChat（OSC。既定ではお使いのPCの中。「OSCの送信先IPアドレス」を変えるとその機器） | 送る文章 |
| VRChatとの連携（OSCQuery、オフにできます） | お使いのPCの中（mDNS。PCの外には送りません） | アプリが動いていることの告知。告知に入るのは`ASTAROT:<起動した時刻>`という名前とポートで、PCの名前やユーザー名は入りません |
| 利用状況の送信（オフにできます） | ASTAROTの開発者（Cloudflare） | 起動したこと、エラーの種類、PCの構成 |
| 更新の確認（起動時、オフにできます）と更新の取得 | 確認は、StableとBetaのどちらのチャンネルも、ASTAROTの開発者（Cloudflare）を通してGitHubへ。取得はGitHub | 最新版の問い合わせとダウンロードの要求。会話や音声、設定は送りません。deb・rpmで入れた場合は確認しません |

選んだ翻訳エンジンは自分の発言のほかに、スピーカーから聞き取った相手の発言とチャット読み取りの文も翻訳します。

Windowsでは、画面を表示する部品（WebView2）がMicrosoftのサーバーへ接続します。アプリではなくWebView2が行う通信で、安全性の確認（SmartScreen）や部品の更新の確認です。アプリの設定では止められません。WebView2が異常終了したときの記録（クラッシュダンプ）はMicrosoftへ送らず、PCの中に残すようにしています。この記録はPCの中にたまっていき、会話の文が入ることがあります。WebView2が集める診断データのうち任意のものは、Windowsの「設定」→「プライバシーとセキュリティ」→「診断とフィードバック」の「診断データ」に従います。

「ONNX Runtime · DirectML」を取得した場合、DirectMLのライセンスには、利用者と使い方の情報を集めてMicrosoftへ送ることがあると書かれています。

ローカルの翻訳モデル、同梱のspeech.cppサーバー（読み上げ・ローカルの音声認識・リアルタイム字幕）、ボイスチェンジャー（RVC）、チャット読み取りはお使いのPCの中で動きます。チャット読み取りのために共有したウィンドウの映像も、PCの外に出ません。

音声認識エンジンは文字起こしを初めてオンにするときに自分で選びます。選んでいないサービスへ音声を送ることはありません。ローカル（speech.cpp）のモデルがないときも、ほかのエンジンへ自動では切り替えません。

OpenAI互換のエンドポイントやCustom WhisperのURLを変えるときは、APIキーを入れ直します。保存済みのキーを新しいURLへ自動では送りません。

## PCに保存されるもの

- 設定ファイル（`config.json`）には、OBSブラウザソースとWebSocketのキーが保存されます。Linuxでは、共有したウィンドウを次回から選択画面なしで共有するための情報が加わります。
- 翻訳や音声認識のAPIキーは設定ファイルに書かず、OSの資格情報の保管場所に保存します。Windowsでは資格情報マネージャー、LinuxではSecret Service（GNOME Keyring、KWalletなど）です。0.5.2までの版は設定ファイルと同じフォルダーの`secrets.json`にキーを保存していました（WindowsではPCにサインインしている本人だけが読み戻せるよう暗号化）。そのキーは更新して起動したときに保管場所へ移します。移せなかったキーは`secrets.json`に残り、そのまま使えます。Linuxで鍵束が動いていないか、ロックされているときは、新しく入れたキーはアプリを閉じるまでしか使えません。
- ログはアプリの動作の記録です。不具合を報告するときは、個人情報や会話の内容を消してから貼ってください。
- 会話のログは「設定」→「高度な設定」の「会話ログを自動的に保存する」をオンにしたときだけ、テキストファイルとして保存します。

保存先は[インストール](./install)と[困ったとき](./troubleshooting)を見てください。

## PCの中で動くサーバー

OBSブラウザソースとWebSocketは、オンにしたときだけ動きます。既定ではPCの中（`127.0.0.1`）からだけつなげます。つなぐには、URLに含まれるキーが必要です（[OBSとWebSocket](../features/integrations)）。
